## APP 登录模块实现方案

为「APP」项目实现一键获取 APP 登录 token：学校下拉（默认「未来智慧学校AI平台」、可搜索/模糊查询）+ 账号自填 + 一键登录拿 token。整体复用现有「其它」站点登录模块的分层架构（background 服务 + popup UI + 消息中转 + 项目开关），登录流程已实测验证。

### 实测确认的登录流程（4 步全在 baseUrl 下走 `/huayun-ai` 前缀）
1. `POST /huayun-ai/client/tenant/educationList`（body `{}`）→ `{code:200,data:[{id,name,...}]}`，**id 即 tenantId**，共 115 所学校，默认校 `id=57`「未来智慧学校AI平台」
2. `POST /huayun-ai/app/auth/getCaptcha`（body `{}`）→ `{data:{ticket, blockX}}`，**blockX 即滑块答案 moveLength**（实测 moveLength=blockX 可直接通过验证码）
3. `POST /huayun-ai/app/auth/studentLogin`（body `{account, password: sha256(明文), tenantId, moveLength: blockX, ticket}`）→ `{data:{accessToken:"Bearer xxx", userId, username, account, tenantId, tenantName, ...}}`
- 鉴权依赖浏览器会话 cookie（`authjs.session-token` 等），由 `credentials: include` + `chrome.cookies` 自动携带，**APP 模块自身不需要 admin token**

### 用户确认的默认值
- 站点地址：留空，由用户填写（持久化，复用 other-login 的 `siteUrl` 模式）
- 默认账号：`202506002`（学生账号，用户可改）
- 默认密码：明文 `Xx@123456`，插件内 SHA-256（与 other-login/api.js 一致）

### 改动文件（7 处）

**1. `src/common/projects.js`** — 为 APP 项目开启 `appLogin` feature
- `app` 项 `enabledFeatures: []` → `['appLogin']`
- 新增 `appLoginApiPaths: { educationList: '/huayun-ai/client/tenant/educationList', getCaptcha: '/huayun-ai/app/auth/getCaptcha', studentLogin: '/huayun-ai/app/auth/studentLogin' }`（集中配置路径，对齐 `tenantApiPaths` 风格）

**2. `src/background/app-login.js`**（新建）— APP 登录后台服务
仿 `other-login.js` 结构，命名空间挂到 `ns.appLogin`：
- 常量：`DEFAULT_ACCOUNT='202506002'`、`DEFAULT_PASSWORD='Xx@123456'`、`CRED_KEY='appLoginCredentials'`、`TOKEN_KEY='appLoginToken'`、`HISTORY_KEY='appLoginHistory'`
- `normalizeSiteUrl / normalizeCreds / defaultCredentials`（站点留空时登录报错提示填写，不复用 other-login 默认）
- `getCredentials / saveCredentials / getToken / saveToken / clearToken`（chrome.storage 持久化）
- `getHistory / recordHistory / deleteHistory`（按 siteUrl+account+tenantId 去重，保留最新，置顶 20 条）
- `encryptPassword(password)`（SHA-256，复用 other-login/api.js 同款实现）
- `postJson(siteOrigin, path, body, {token})`：拼 `${origin}${path}`（路径已含 `/huayun-ai` 前缀），`credentials:'include'` + `chrome.cookies` 取 `HWWAFSESID/HWWAFSESTIME/authjs.session-token/authjs.csrf-token` 注入 Cookie 头，带 Origin/Referer
- `listSchools({siteUrl})`：调 educationList，规范化为 `[{tenantId:id, tenantName:name, domain, fullName}]`，返回全量列表（前端做模糊搜索）
- `extractTicket / extractMoveLength`（取 `data.ticket` / `data.blockX`）
- `extractAccessToken`（去 `Bearer ` 前缀）、`extractUserSummary`（取 username/account/tenantId/tenantName/studentId 等）
- `doLogin({siteUrl, account, password, tenantId})`：校验 siteUrl 非空 → 存凭据 → getCaptcha → sha256(密码) → studentLogin（moveLength 用 blockX）→ 存 token → 返回 `{token,user,siteUrl,account,tenantId,tenantName,loginRes}`；`success===false` 抛 `extractErrorMessage`
- 导出：`DEFAULT_ACCOUNT/DEFAULT_PASSWORD, getCredentials, saveCredentials, getToken, saveToken, clearToken, getHistory, recordHistory, deleteHistory, listSchools, doLogin`

**3. `src/background/index.js`** — 新增 APP 消息分支（紧跟「其它」分支后）
`APP_LIST_SCHOOLS / APP_LOGIN / APP_GET_CREDENTIALS / APP_SAVE_CREDENTIALS / APP_GET_TOKEN / APP_SAVE_TOKEN / APP_CLEAR_TOKEN / APP_GET_HISTORY / APP_DELETE_HISTORY`，均 `ns.appLogin.*().then(...).catch(...)`，与现有 `OTHER_*` 分支一一对应。

**4. `src/popup/app-login-ui.js`**（新建）— APP 登录面板 UI
仿 `other-login-ui.js`，命名空间挂到 `ns.appLoginUi`，ID 前缀 `app`：
- 状态：`state = { schools:[], filtered:[], selectedSchool, schoolsLoaded, loading, historyExpanded }`
- `renderCredentials()`：填 siteUrl/account/password（默认账号 202506002、默认密码 Xx@123456）
- `loadSchools()`：`APP_LIST_SCHOOLS` → 缓存全量，默认选中 `tenantName==='未来智慧学校AI平台'`（无则选首条）
- 学校选择器：`<input id="appSchoolSearch">` + `<div class="list" id="appSchoolList">` 下拉，`input` debounce 300ms 模糊匹配 `tenantName`（含空格分词匹配），点击选中后回填搜索框、收起列表
- `handleLogin()`：校验 siteUrl/account/password/selectedSchool → `APP_LOGIN` → `renderToken()` → toast 成功 → `renderHistory()`
- `renderToken()`：可编辑 token 区（失焦保存，复用 other-login 同款 editable 模式）+ 用户 meta（username · tenantName）+ 复制按钮
- `renderHistory()`：最近登录列表（一键重登 + 删除），按 siteUrl+account 去重，与 other-login 历史样式一致
- `init()`：bindEvents + renderCredentials + renderToken + renderHistory + loadSchools

**5. `popup.html`** — 新增 APP tab + panel
- tab-rail 增加 `<button class="tab-btn" data-tab="app"><span class="tab-icon">📱</span>APP</button>`
- 新增 `<div class="panel" id="panel-app">`：站点地址、学校选择（搜索框+下拉列表）、账号、密码（含显隐切换）、一键登录按钮、callout 说明、历史记录、Access Token 区（结构镜像 panel-other，ID 前缀 `app`）

**6. `src/popup/index.js`** — 接入 APP 面板
- `bindTabSwitcher()` 的 `panels` 增加 `app: $('panel-app')`
- `init()`：APP 项目时隐藏 admin/quick/other 三个 tab（仅显示 app tab）；`enabledFeatures.includes('appLogin')` 时 `await ns.appLoginUi.init()`；空项目占位逻辑保留兼容

**7. `scripts/build.js`** — 打包加入新文件
- `popupFiles` 末尾（index.js 前）加 `'src/popup/app-login-ui.js'`
- `backgroundFiles` 末尾（index.js 前）加 `'src/background/app-login.js'`

### 实现约束与对齐点
- 项目切换隔离：APP 项目 `enabledFeatures:['appLogin']` 不含 `adminPanel/quickLogin`，popup 仅显示 APP tab，token/凭据/历史用独立 storage key（`appLogin*`），与 admin(`adminToken:*`)/other(`otherLogin*`) 完全隔离，互不串号
- 加密对齐：SHA-256 与 `other-login.js`/`api.js` 同款（`crypto.subtle.digest` → hex），保证与服务端校验一致
- Cookie 鉴权：`postJson` 用 `credentials:'include'` + `chrome.cookies.get` 补 WAF/会话 cookie，与 other-login 一致；不依赖任何 admin token
- 风格对齐：UI/消息/storage 全部镜像现有「其它」模块，无新依赖、无新构建工具
