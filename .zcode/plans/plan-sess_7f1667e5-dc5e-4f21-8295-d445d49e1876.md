## 问题根因

四个问题都源于「mock 编辑数据未完整持久化」与「关闭/开启态数据来源混淆」：

1. **重开丢 mock 出入参数据**：切 Tab 时未保存离开 Tab 的草稿；`buildRule` 只写 `activeTab` 的 mockData。编辑出参→切入参→切开关→重渲染，出参的编辑仅存在于 `editorDrafts` 内存，从未落盘，被旧规则覆盖。
2. **关闭后不出真实数据**：已编规则下 `ctx.responsePayload/requestPayload` 取自 `captured` 快照，快照缺失时显示 `null`；且无「无入参→空状态」处理。
3. **Method/URL/Status 关闭后丢、重开不复原**：关闭态头部回退到 `ctx.method/url/status`（捕获值），丢失 mock 值；且非导入接口的 URL/Method 根本不可编辑（`#editUrl` 仅 `isImported` 渲染），mock 的 Method/URL 无法持久化。
4. **无入参不显示空状态**：入参 Tab 在 `requestPayload` 为空时直接显示 `null`。

## 修复方案（panel.js 为主，mock-hook.js 微调）

### 1. 规则结构补充 mock Method/URL 持久化字段
在 `getMockParts` 与 `buildRule` 中，将 mock 的 Method/URL 也纳入规则持久化（与 Status 同级，作为顶层 mock 字段），保证「开关解耦、关闭不丢、重开复原」：
- 规则新增顶层 `mockMethod`、`mockUrl`（仅开启拦截时由面板编辑值写入；关闭时不覆盖，保留之前值）。
- `responseMock.status` 已存在，保留。

### 2. Tab 切换时持久化离开 Tab 的草稿（修 Bug 1）
`renderEditor` 中 Tab 切换处理：切换前先调用 `autoSaveMockRule(activeTab, jsonEditor, {silent:true})` 把当前 Tab 的编辑落盘，再切到目标 Tab。这样两个方向的 mockData 始终同步到规则，重渲染不丢。

### 3. 重构数据回填逻辑：明确「真实数据」vs「mock 数据」两套来源（修 Bug 2/3）
- **真实数据**（关闭态显示）：`ctx.responsePayload`/`ctx.requestPayload`/`ctx.status`/`ctx.method`/`ctx.url` —— 始终来自捕获快照或实时请求，与规则 mock 无关。
- **mock 数据**（开启态显示）：`parts.responseMock.mockData`/`parts.requestMock.mockData`/`parts.responseMock.status`/`rule.mockMethod`/`rule.mockUrl` —— 来自规则，关闭时保留不动。
- `buildContext` 保持现状（真实数据源）；`renderEditor` 头部与编辑器按 `interceptOn` 选择展示哪套：
  - 开启：头部显示 `mockMethod/mockUrl/status`（可编辑），编辑器显示 mockData。
  - 关闭：头部显示真实 `ctx.method/url/status`（只读），编辑器显示真实 payload（只读）。
- 头部可编辑性：开启拦截后 **所有接口**（含捕获态）均可编辑 Method/URL/Status，不再限制为仅 `isImported`。URL 编辑值写入 `mockUrl`。

### 4. 入参空状态（修 Bug 4）
`draftFor('request')` 在真实入参为空（null/undefined/`{}`/`[]`）且无 mockData 时，编辑器区域渲染空状态提示「该接口无入参」，而非 `null`。具体：入参 Tab 下若 `ctx.requestPayload == null` 且 `parts.requestMock.mockData == null` → 显示空态卡片（替换 json-frame 内容）。

### 5. buildRule 调整
- `finalUrl`/`finalMethod`：开启拦截时优先取面板字段值（`mockUrl`/`mockMethod`），写入规则顶层；关闭时沿用既有 `rule.mockUrl/mockMethod`（不覆盖）。注意：`rule.url`/`rule.method` 仍为匹配用的真实值（mock-hook 按此匹配），mock 的 Method/URL 仅影响「展示与拦截响应构造」——为简化，mock Method/URL 仅在面板展示与持久化，mock-hook 仍按 `rule.url`/`rule.method` 匹配（Method 匹配保持真实 method，避免改 Method 后拦截失效）。
- `mockData`：始终从编辑器读取当前 activeTab 内容写入对应方向。
- enabled：开=两方向都 true，关=都 false，mockData/Method/URL/Status 全部保留。

### 6. mock-hook.js 微调
出参拦截构造假响应时，`status` 已读 `responseMock.status`，无需改动。mock Method/URL 不影响拦截匹配（仍按真实 url+method 命中），故 mock-hook 无需改动 Method/URL 逻辑。确认即可。

## 不改动
- mock-storage.js 迁移逻辑（已正确）。
- 禁监、导入、列表渲染、上下文失效提示。
- build.js。

## 验证
- `npm run build` + `node --check devtools/panel.js`。
- 手测：开拦截→编辑出参→切入参编辑→关拦截（头部与数据区变真实数据、只读）→重开拦截（出参与入参 mock 数据、Method/URL/Status 全恢复）→清空（归零）。无入参接口切到入参 Tab 显示空状态。
