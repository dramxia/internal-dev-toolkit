## 目标

统一"捕获"与"已编"职责，并放开 mock 开关开启后的请求方式/状态编辑：
- **捕获**：自动捕获页面网络请求。在此开启 mock 开关后，规则仍持久化（hook 才能拦截），但**不进"已编"列表**；开启 mock 后支持改 Method/Status，URL 只读。
- **已编**：用户主动添加（导入）的接口。支持改 URL + Method + Status。
- 不改变 Method/Status 控件位置（仍在编辑器头部）。

## 标记方案

用 `captured.source` 区分两类规则（hook 不关心此字段，照常拦截）：
- 捕获态规则：`captured.source === 'capture'`（新增）→ 不显示在"已编"列表
- 导入态规则：`imported === true` 或 `captured.source === 'imported'`（已有）→ 显示在"已编"列表

## 改动点（全部在 `devtools/panel.js`）

### 1. `buildRule`（约 1395-1435）— 标记捕获态 + 放开 status 写入
- `ctx.mode === 'capture'` 分支里给 `rule.captured` 增加 `source: 'capture'`。
- 移除 `if (imported) { rule.status = s }` 的 imported 限制，改为任何规则都写顶层 `rule.status`（hook 的 `mockStatus` 读取，默认 200）。这样捕获态开启 mock 后改 Status 才能持久化生效。
- 更新顶部注释。

### 2. `renderEditor` 头部（约 1008-1035）— 放开 Method/Status 可编辑条件
- 当前：`isImported` 才渲染可编辑 URL/Method/Status，否则全只读。
- 改为：
  - `const canEditHeader = interceptOn;`（mock 开关开启即可编辑 Method/Status）
  - URL 仅 `isImported` 可编辑（已编接口才改 URL，改 URL 会改变 hook 匹配，捕获态保持只读）
  - Method/Status 在 `canEditHeader` 时渲染为 `<select>`/`<input>`，否则只读
- 头部字段拼接：导入且可编辑→ URL input + Method select + Status input；非导入但可编辑→ URL 只读 span + Method select + Status input；否则全只读。
- 控件位置不变（仍在 editor-header 内，顺序保持 Method/URL/Status 与现有一致）。

### 3. `renderEditedList`（约 845-862）— 过滤捕获态规则
- 在现有 monitor-disabled 过滤基础上，再排除 `captured.source === 'capture'` 的规则，使捕获态规则不进"已编"列表。
- 过滤条件：`r.captured?.source !== 'capture'`（导入态无 source 或 source='imported'，均保留）。

### 4. `loadData` 计数角标（约 759-766）— 已编计数排除捕获态
- `visibleEdited` 过滤增加 `r.captured?.source !== 'capture'`，与 renderEditedList 保持一致。

## 不改动的部分
- hook（mock-hook.js）/ content script / background / storage：无需改动。hook 照常按 mockRules 拦截，`source` 字段对 hook 透明。
- 控件位置、CSS、禁监功能、轮询选中修复：保持现状。
- `findRuleForRequest` 仍按 url+method 精确匹配，捕获态规则开启 mock 后仍能被找到（`interceptOn` 为 true）。

## 行为预期
- 捕获 tab 选中请求 → 开 mock 开关 → 规则存入 mockRules（`source:'capture'`）→ 不出现在"已编"列表，"已编"计数不含它 → 头部 Method/Status 变为可编辑 → 改值保存生效（hook 按新 method/status 拦截）。
- 已编 tab 选中导入接口 → 头部 URL/Method/Status 均可编辑。
- 未开 mock 的捕获请求 → 头部全只读（与现状一致）。
