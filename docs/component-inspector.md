# 本地 React／Vue 组件定位

适用环境：macOS、Chrome 116 及以上版本、Node.js 18 及以上版本、本机直接启动的 React 或 Vue 开发项目。

## 安装与第一次使用

1. 在工具箱项目目录执行 `pnpm install`，再执行 `pnpm build`。
2. 在 `chrome://extensions` 重新加载工具箱扩展。
3. 打开工具箱底部的「定位」。顶部显示当前标签页的状态与开关，首次使用时自动展开「辅助程序」。
4. 点击「复制安装命令」。按 Command + 空格，搜索并打开「终端」，粘贴命令后按回车，等待成功提示。命令已包含所需文件和扩展编号，可在任意目录执行。
5. 返回「定位」页，页面会自动检查连接，也可点击「检查连接」。连接成功后自动展开「编辑器」，点击「选择编辑器」，文件窗口默认打开「应用程序」目录，选中编辑器的 `.app` 文件，也可以浏览其他目录。
6. 打开本地 React／Vue 开发页面，打开顶部的定位开关。项目目录会根据开发端口、服务进程和源码信息自动识别。

日常使用时，编辑器、快捷键、开发地址和辅助程序默认收起。点击对应设置可修改；点击当前开发地址可查看完整页面地址、框架、项目目录和最近打开的文件。状态刷新失败时，点击「重新检查」恢复。

本机辅助程序安装一次，所有本地开发项目共用。之后重新加载扩展，打开「定位」页或启动组件定位时，会自动检查并同步当前扩展附带的辅助程序。编辑器选择和项目记录会保留。完整安装命令将程序安装到当前用户目录并注册 Chrome 通信。系统安全设置保持原样。页面可展开「查看完整安装命令」检查内容；自动复制失败时会选中命令，按 Command + C 手动复制即可。

若终端提示找不到 node，请先安装 Node.js 18 或以上版本，再执行命令。旧版辅助程序尚未提供自动更新功能，需要最后点击一次「复制重装命令」并执行；此后可自动同步后续修改。

备用安装包位于「辅助程序 → 安装帮助与修复」中。下载的 `.command` 文件尚未经过 Apple 签名和公证，双击时可能出现「Apple 无法验证」提示。[Apple 对此提示的说明](https://support.apple.com/zh-cn/102445)

遇到此提示，可清除本次安装包的下载隔离标记后再打开：

1. 点击「复制解除隔离命令」，将命令粘贴到终端，末尾保留一个空格。
2. 将本次解压得到的 `component-helper` 文件夹拖到命令末尾，再按回车。拖入文件夹会自动填入它的实际路径。
3. 重新双击「安装.command」。

命令格式如下，路径使用你实际解压的位置：

```sh
xattr -dr com.apple.quarantine "/实际路径/component-helper"
```

`-d` 删除指定属性，`-r` 递归处理所选目录。`xattr -cr` 则会清除目录内的全部扩展属性，这里仅需删除 `com.apple.quarantine`。首次解除隔离要在终端执行，被系统拦截的脚本此时尚未启动。也可以直接使用页面上方的完整安装命令。

旧版辅助程序使用应用列表选择器。完成这次升级后，自动更新与新的 `.app` 文件选择窗口一并启用。取消选择会保留原编辑器。

编辑器初始为空。选好编辑器、连接本机程序且项目目录识别成功后，页面上的定位功能才会开启。

## 使用

- 按住 **Command** 移动鼠标：高亮页面元素并显示对应组件。
- **Command + 单击**：打开最近一个提供源码位置的组件。
- **Command + 右键**：查看组件与父组件列表。
- 菜单中使用上下方向键选择组件，右方向键查看组件参数（props），左方向键收起，回车打开，Escape 关闭。
- 管理页点击快捷键按钮可以录制新组合，松开后保存。

VS Code、VS Code Insiders、Cursor 和通过 Chrome 安装的 TermRelay 支持行列跳转。其他系统窗口中选中的软件通过 macOS 打开文件。有精确行列时显示具体位置，只有文件路径时显示「文件定位」。

VS Code 和 VS Code Insiders 通过系统发送文件链接，优先使用已运行的所选应用，并按文件路径寻找对应的项目窗口。项目在父目录或多文件夹工作区中打开时，也由 VS Code 选择对应窗口。首次打开链接时，按编辑器提示确认打开文件。

使用 TermRelay 时，先启动本机 TermRelay 服务，在 Chrome 打开页面并安装为应用，再在第 2 步选择该 `TermRelay.app`。它通常位于当前用户的「应用程序 → Chrome 应用」目录。定位时会唤起已有的 TermRelay 窗口，在文件标签页打开源码并定位行列；文件所属项目尚未导入时，按提示选择项目文件夹并导入。首次打开定位链接时，按 Chrome 提示允许应用处理链接。旧版安装的应用提示缺少定位入口时，通过 Chrome 重新安装后再选择。

开关按开发地址保存，地址由协议、主机和端口共同确定。例如 `http://localhost:5173/users` 和 `http://localhost:5173/orders` 共用一个开关。同地址的所有标签页一起开启、一起停止；切换路由、刷新页面、重新打开标签页和重启浏览器后，都会沿用已保存的开关。切换到其他开发地址时，使用该地址自己的开关。

切换路由后可以继续按快捷键定位组件，无需刷新页面或重新开关。同地址刷新时沿用已识别的框架和项目目录，检查开发服务仍有效后，立即恢复页面上的定位脚本；页面结构加载完成即可恢复，图片等资源可以继续加载。开发服务重启或项目记录变化后，会自动重新识别。首次打开页面时，React／Vue 组件延迟加载会等待组件挂载后自动启用。识别或恢复超时时显示具体提示，保留开关，处理提示后点击「检查连接」重试。

开发服务停止或重启时，开关继续保留。已开启的页面会定期检查服务，离线时显示「等待开发服务」；同一开发地址重新上线后，会自动识别新进程和项目目录、更新源码映射并恢复定位。源码跳转遇到旧服务记录时，会自动重新识别并重试。等待期间手动关闭开关后，会沿用关闭状态。

正常运行时，可见页面约每 15 秒检查一次，隐藏页面约每 60 秒检查一次；同一开发地址共用检查结果。发现服务离线后，可见页面按 1、2、4、8、15 秒的间隔重试，之后保持约每 15 秒一次。切回页面或窗口重新获得焦点时会触发检查，源码跳转时也会核对服务，尽快恢复定位。

源码文本缓存最多保留 32 份，总大小按每个字符两个字节估算，上限为 16 MB。达到上限时优先清理较久未用的内容，闲置 5 分钟后自动释放；并发读取同一资源会合并下载。刷新页面、重新识别项目或关闭该地址的定位时，会清理对应地址的旧缓存。

## 项目目录与地址

默认支持 `localhost`、`127.0.0.1`、`::1` 的 HTTP／HTTPS 页面。自定义开发域名或本机局域网地址可在管理页添加，设置按协议、主机和端口保存。

辅助程序读取监听端口的服务进程、工作目录和启动参数，并结合组件文件路径检查项目目录。识别有歧义时，页面会暂停并显示原因。修正服务启动方式后，点击「检查连接」重新识别。

支持从共同父目录统一启动前端的多项目工程，也支持普通文件夹下放置多个独立前端项目。辅助程序先根据启动参数、进程工作目录和源码绝对路径确定项目；信息不足时，再向下查找包含 `package.json` 的子项目，用当前页面的组件源码路径确认对应目录。父目录可以省略 `package.json`、`pnpm-workspace.yaml` 和 `workspaces` 配置。例如 TermRelay 在仓库根目录执行 `pnpm dev`，网页前端会识别为 `apps/web`，随后可打开其中的 `.tsx` 源码。

子项目查找最多向下四层、检查 256 个目录，跳过依赖目录、构建产物、隐藏目录和目录软链接。已经匹配到源码的独立项目会直接使用识别结果，减少额外扫描。多个子项目的源码路径同样吻合时，会提示检查开发服务的启动目录；缺少有效源码路径时，会显示识别失败。

源码信息来自页面运行中的 React Fiber、Vue 组件实例和开发服务器已有的源码映射。React 18 使用源码字段；React 19 使用调试调用栈和源码映射；Vue 2／3 使用组件文件信息及页面已有的位置标记。业务项目的文件保持原样。

## 本机辅助程序

页面按钮是推荐入口；习惯终端操作的用户也可以在工具箱目录执行：

```sh
node scripts/install-component-host.js <扩展编号>
```

安装程序将启动器和各版本的运行文件保存到
`~/Library/Application Support/InternalDevToolkit/component-host/`，记录当前 Node.js 的绝对路径，并为指定扩展注册 Chrome 原生通信。

辅助程序按文件内容判断是否更新，修改源码后无需手动增加版本号。打开「定位」页时，扩展将自带的更新文件通过 Chrome 原生通信发送到本机；辅助程序先校验内容、在独立目录准备文件，并检查新程序能够启动，再切换到新版。扩展随后自动重连。内容相同时跳过更新。

更新仅使用当前扩展附带的文件。更新失败时保留原版本；页面会显示原因，点击「检查连接」重试。启动器会保留上一版完整文件，用于当前版本损坏时恢复。需要修复安装时，仍可复制并执行重装命令。

编辑器设置保存在 `~/Library/Application Support/InternalDevToolkit/settings.json`。
Node.js 安装路径发生变化、扩展编号变化时，重新执行安装命令。

卸载时，在「定位 → 辅助程序」中点击「卸载」，确认后会停止所有页面的组件定位，移除本机程序与 Chrome 通信注册，并保留编辑器设置。

连接失效或辅助程序版本较旧时，按钮显示「复制卸载命令」。在终端粘贴并按回车，完成后回到页面点击「检查连接」。

也可以在工具箱目录执行：

```sh
node scripts/install-component-host.js --uninstall
```

卸载会移除程序和 Chrome 通信注册，保留编辑器设置。

## 常见提示

| 提示 | 处理方法 |
|---|---|
| 请先安装本机辅助程序 | 点击「复制安装命令」，打开终端粘贴并按回车 |
| Apple 无法验证「安装.command」 | 按「复制解除隔离命令」后的步骤处理本次安装包，再双击安装；或使用完整安装命令 |
| 启用辅助程序自动更新 | 旧版用户最后手动重装一次，此后随扩展自动同步 |
| 辅助程序更新未完成 | 点击「检查连接」重试；仍失败时用重装命令修复 |
| 请先选择有效的编辑器 | 从「应用程序」目录选择编辑器 `.app`；编辑器移动后重新选择 |
| 未找到监听端口的本机开发服务 | 确认开发服务运行中、页面端口正确 |
| 等待页面加载 | 开关已保存，React／Vue 组件挂载后会自动启用 |
| 项目目录识别失败 | 检查服务启动目录及启动参数，再点击「检查连接」 |
| 等待开发服务 | 保持开关开启，同一开发地址的服务恢复后会自动重新识别项目并恢复定位 |
| 此组件尚未提供源码位置 | 在父组件菜单中查看其他组件；开发构建和源码映射会影响可读取的位置 |

Docker、代理和远程端口转发需要额外的路径对应信息。当前目录识别针对本机直接启动的开发服务。
